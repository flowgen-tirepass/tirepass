## 📋 마이그레이션이란?

Django 마이그레이션은 데이터베이스 스키마 변경을 추적하고 적용하는 시스템입니다.
- 모델 변경 → 마이그레이션 파일 생성 → 데이터베이스에 적용

---

## 🔍 1단계: 현재 마이그레이션 상태 확인

### PythonAnywhere Bash 콘솔에서 실행:

```bash
# 1. 프로젝트 디렉토리로 이동
cd ~/tirepass

# 2. 가상환경 활성화 (필요한 경우)
source venv/bin/activate

# 3. 마이그레이션 상태 확인
python manage.py showmigrations
```

### 출력 예시:

**해석**:
- `[X]`: 적용된 마이그레이션
- `[ ]`: 적용 안 된 마이그레이션 (이런 항목이 있으면 적용 필요)

---

## ✅ 2단계: 미적용 마이그레이션이 없는 경우

모든 마이그레이션에 `[X]` 표시가 있으면:
- ✅ **마이그레이션 적용 완료**
- 추가 작업 불필요

---

## ⚠️ 3단계: 미적용 마이그레이션이 있는 경우

`[ ]` 표시된 마이그레이션이 있으면:

### 방법 1: 마이그레이션 적용

```bash
python manage.py migrate
```

**출력 예시**:
```
Operations to perform:
  Apply all migrations: tire_data, admin, auth, contenttypes, sessions
Running migrations:
  Applying tire_data.0029_new_migration... OK
```

### 방법 2: 특정 앱만 마이그레이션

```bash
python manage.py migrate tire_data
```

---

## 🆕 4단계: 새로운 마이그레이션 파일 생성 (필요한 경우)

모델을 변경했다면 마이그레이션 파일을 생성해야 합니다:

```bash
# 1. 변경사항 감지 및 마이그레이션 파일 생성
python manage.py makemigrations

# 2. 생성된 마이그레이션 적용
python manage.py migrate
```

**출력 예시**:
```
Migrations for 'tire_data':
  tire_data/migrations/0030_auto_20251122_1230.py
    - Add field new_field to customers
    - Alter field name on goods
```

## 🔄 5단계: 마이그레이션 충돌 해결

### 충돌이 발생한 경우:

```
CommandError: Conflicting migrations detected; multiple leaf nodes in the migration graph
```

**해결 방법**:

```bash
# 1. 충돌 확인
python manage.py showmigrations tire_data

# 출력에서 여러 branch가 있는지 확인
tire_data
 [X] 0027_add_point_system
 [X] 0028_add_policy_pages
 [ ] 0029_branch_a  ← 충돌
 [ ] 0029_branch_b  ← 충돌

# 2. 병합 마이그레이션 생성
python manage.py makemigrations --merge

# 3. 적용
python manage.py migrate
```

## ✨ 배포 시 권장 순서

### PythonAnywhere에서 배포할 때:

```bash
# 1. 프로젝트 디렉토리로 이동
cd ~/tirepass

# 2. Git에서 최신 코드 가져오기
git pull origin main

# 3. 가상환경 활성화 (필요한 경우)
source venv/bin/activate

# 4. 의존성 업데이트 (requirements.txt가 변경된 경우)
pip install -r requirements.txt

# 5. 새로운 마이그레이션 파일 생성 (모델 변경이 있는 경우)
python manage.py makemigrations

# 6. 마이그레이션 적용
python manage.py migrate

# 7. 정적 파일 수집
python manage.py collectstatic --noinput

# 8. 웹 앱 재시작
# Web 탭 → Reload 버튼 클릭
```

## 🚨 주의 사항

### 1. 프로덕션 환경에서 주의할 점

- ⚠️ **데이터 손실 위험**: 마이그레이션 전 데이터베이스 백업 권장
- ⚠️ **다운타임**: 큰 테이블의 스키마 변경은 시간이 걸릴 수 있음
- ⚠️ **롤백 준비**: 문제 발생 시 롤백 계획 수립

### 2. 백업 방법 (운영 환경)

```bash
# MySQL 데이터베이스 백업
mysqldump -u tirepass -p \
  -h tirepass.mysql.pythonanywhere-services.com \
  tirepass$itire_db > backup_$(date +%Y%m%d_%H%M%S).sql

# 복원 (필요한 경우)
mysql -u tirepass -p \
  -h tirepass.mysql.pythonanywhere-services.com \
  tirepass$itire_db < backup_20251122_123000.sql
```

### 3. managed=False 모델 주의

다음 모델들은 `managed=False`이므로 마이그레이션 적용 안 됨:
- `Goods` (ERP 연동)
- `CustomersFull` (ERP 연동)

이 테이블들은 ERP 서버에서 관리되므로 Django에서 스키마 변경하지 않습니다.

## 🔍 문제 해결

### 문제 1: "No migrations to apply"

**원인**: 모든 마이그레이션이 이미 적용됨
**해결**: 아무 작업 불필요

### 문제 2: "Table already exists"

**원인**: 데이터베이스에 테이블이 이미 존재하는데 마이그레이션이 적용 안 된 것으로 표시됨

**해결 방법**:

```bash
# 마이그레이션을 적용된 것으로 표시 (실제 DB 변경 없이)
python manage.py migrate --fake tire_data
```

### 문제 3: "Programming Error: column does not exist"

**원인**: 마이그레이션이 제대로 적용되지 않음

**해결 방법**:

```bash
# 1. 현재 상태 확인
python manage.py showmigrations

# 2. 마이그레이션 다시 적용
python manage.py migrate

# 3. 여전히 문제가 있으면 특정 마이그레이션부터 다시 적용
python manage.py migrate tire_data 0028
python manage.py migrate tire_data
```

### 문제 4: 마이그레이션 파일 충돌

**해결 방법**:

```bash
# 병합 마이그레이션 생성
python manage.py makemigrations --merge
```

## 🎯 빠른 확인 스크립트

```bash
#!/bin/bash
# check_migrations.sh

echo "=== 마이그레이션 상태 확인 ==="
python manage.py showmigrations

echo ""
echo "=== 미적용 마이그레이션 확인 ==="
PENDING=$(python manage.py showmigrations --plan | grep "\[ \]" | wc -l)

if [ $PENDING -eq 0 ]; then
    echo "✅ 모든 마이그레이션이 적용되었습니다."
else
    echo "⚠️ 적용 안 된 마이그레이션이 $PENDING 개 있습니다."
    echo "다음 명령을 실행하세요: python manage.py migrate"
fi
```
