## 당신이 강의할 자격이 있는 이유

### ✅ 자격 있습니다! 이유는:

#### 1. **실전 경험이 있습니다**
- 이론서 읽은 게 아니라 **직접 만들었습니다**
- 35일간 331번의 커밋 = 331번의 시행착오
- 실제 고객사가 사용하는 시스템 완성
- **실전 경험 > 학위/자격증**

#### 2. **청중과 같은 입장이었습니다**
- 59세, 비전공자, 코딩 경험 0
- 청중의 어려움을 100% 이해합니다
- 어디서 막히는지, 무엇이 어려운지 압니다
- 공감 능력이 강의의 핵심입니다

#### 3. **"가능하다"는 증거입니다**
전문가가 말하면: "저 사람은 원래 잘하니까..."
당신이 말하면: "저 사람도 했으면 나도 할 수 있겠다!"

→ **당신의 이야기가 청중에게 용기를 줍니다**

#### 4. **겸손함이 장점입니다**
"저는 전문가 아닙니다" = 청중과의 거리를 좁힙니다
"저도 실수 많이 했습니다" = 청중의 두려움을 덜어줍니다
"함께 배워가요" = 편안한 학습 분위기를 만듭니다

### ❌ 당신이 가르칠 수 없는 것:
- 컴퓨터 공학 이론
- 알고리즘 최적화
- 대규모 시스템 설계
- 전문 개발자 과정

### ✅ 당신이 가르칠 수 있는 것:
- **"비전공자가 AI로 실전 앱 만드는 법"**
- 이것만으로 충분합니다!

## PPT 변환 방법

### 방법 1: 수동 변환 (추천)

**장점**: 완전한 커스터마이징 가능
**시간**: 2-3시간

**단계:**
1. PowerPoint 또는 Google Slides 열기
2. 테마 선택 (심플한 디자인 추천)
3. 마크다운 파일 열기
4. 각 슬라이드 내용 복사 → 붙여넣기
5. 발표자 노트를 "노트" 섹션에 추가

**팁:**
- 폰트: 나눔고딕 또는 맑은 고딕 (가독성 좋음)
- 크기: 제목 40pt, 본문 24-28pt
- 색상: 검은색 텍스트, 파란색 강조
- 이미지: 필요시 무료 이미지 추가 (unsplash.com)

### 방법 2: AI 활용 변환

**Claude Code를 사용:**

```
"이 마크다운 파일을 PowerPoint 형식으로 변환해줘.
각 슬라이드의 내용과 발표자 노트를 분리해서
PowerPoint에 붙여넣을 수 있는 형식으로 만들어줘."
```

### 방법 3: 온라인 도구

**Marp 사용** (마크다운 → PPT):
1. marp.app 접속
2. 마크다운 업로드
3. PDF 또는 PPTX 다운로드

**주의**: 발표자 노트는 별도 처리 필요

## 강의 진행 팁

### 🎤 발표 전 준비 (1주일 전)

#### 1. 리허설 (3-5회)
- 발표자 노트 소리 내어 읽기
- 타이머 사용해서 시간 체크
- 가족/동료 앞에서 연습

#### 2. 데모 준비
- Claude Code 계정 로그인 확인
- 실제 화면 공유 준비
- "계산기 만들기" 라이브 데모 연습

#### 3. 백업 자료
- 인터넷 끊길 경우 대비
- 슬라이드 PDF 버전 준비
- USB에 자료 백업

### 💡 발표 중 팁

#### 1. 시작할 때 (첫 5분이 중요!)
- **웃으면서 시작**: "여러분, 제가 59세인데 앱 만들었어요!"
- **손 들게 하기**: "코딩 전혀 모르시는 분?"
- **공감대 형성**: "저도 그랬습니다"

#### 2. 중간에
- **시선 분산**: 한 사람만 보지 말고 골고루
- **질문 던지기**: "여러분은 어떻게 생각하세요?"
- **유머 섞기**: "제가 실수한 얘기 들려드릴까요?" (웃음)
- **휴식**: 30분마다 스트레칭 권유

#### 3. 끝날 때
- **행동 촉구**: "오늘 집에 가서 10분만 투자해보세요"
- **연락처 공유**: "언제든 물어보세요"
- **감사 인사**: "여러분의 시간 감사합니다"

### 🚫 피해야 할 것

#### 1. 전문 용어 남발
❌ "API를 RESTful하게 구현했어요"
✅ "다른 프로그램이랑 대화하는 통로를 만들었어요"

#### 2. 너무 빠른 진행
- 한 슬라이드당 최소 3분
- 청중 반응 확인하며 조절
- "이해되시나요?" 자주 물어보기

#### 3. 완벽주의
- "이것도 할 수 있어요, 저것도 할 수 있어요"
- → 과장하지 말고 솔직하게
- 한계도 명확히 말하기

#### 4. 일방적 강의
- 청중 질문 환영
- 중간중간 의견 물어보기
- "혹시 비슷한 경험 있으신 분?"

### 📱 라이브 데모 팁

#### 계획된 데모:
1. **Claude Code 접속** (2분)
   - 브라우저 열기
   - 로그인
   - 새 프로젝트 시작

2. **간단한 프로그램 만들기** (5분)

   - 코드 실행

3. **에러 시연** (3분)
   - 일부러 잘못된 값 입력
   - 에러 메시지 복사

   - 해결되는 과정 보여주기

#### 데모 주의사항:

## 예상 질문과 답변

### 질문 1: "저는 65세인데 너무 늦은 거 아닌가요?"
**답변:**
"전혀요! 저도 59세니까 비슷하잖아요. 나이는 정말 숫자일 뿐이에요. 중요한 건 배우고 싶은 의지입니다. 제가 할 수 있었으면 여러분도 충분히 하실 수 있어요."

### 질문 2: "수학을 못하는데 가능한가요?"
**답변:**
"저도 수학 못해요. (웃음) 사실 비코딩은 수학이 거의 필요 없어요. 더하기 빼기 정도만 알면 충분합니다. AI가 복잡한 계산은 다 해주거든요."

### 질문 3: "월 3-5만원이 부담되는데요?"
**답변:**
"이해합니다. 다만 이렇게 생각해보세요. 외주 맡기면 500만원 이상이에요. 2달 투자하면 약 7만원이고, 평생 쓸 수 있는 프로그램이 나옵니다. 커피 20잔 값으로 새로운 능력을 얻는 거죠."

### 질문 4: "영어를 전혀 못하는데요?"
**답변:**
"저도 영어 못해요! Claude는 한국어를 완벽하게 이해합니다. 제가 35일 동안 영어 한 마디도 안 썼어요. 가끔 에러 메시지가 영어로 나오는데, 그냥 복사해서 Claude한테 보여주면 한국어로 설명해줘요."

### 질문 5: "시간이 없는데 가능한가요?"
**답변:**
"저도 낮에는 영업 일로 바빴어요. 퇴근 후 2-3시간씩 투자했어요. 주말에 조금 더 하고요. 중요한 건 매일 조금씩 하는 거예요. 하루 10시간씩 3일보다, 하루 2시간씩 15일이 훨씬 효과적입니다."

### 질문 6: "혼자 해야 하나요? 도움받을 곳은?"
**답변:**
"Claude가 24시간 선생님이에요. 막히면 Claude에게 물어보면 됩니다. 그리고 저한테도 연락 주세요. (연락처 공유) 비슷한 경험을 한 사람으로서 도와드릴 수 있어요."

### 질문 7: "실패하면 어쩌죠?"
**답변:**
"저도 실패 많이 했어요. OCR 기능도 포기했고, 음성 주문도 안 됐어요. 근데 그게 문제가 아니에요. 빠르게 실패하고, 다음으로 넘어가면 돼요. 전통적인 개발이었으면 몇 주 걸렸을 걸, 비코딩은 며칠 만에 '안 되겠다' 판단하고 넘어갈 수 있어요."

### 질문 8: "완성 후 유지보수는 어떻게 하나요?"
**답변:**
"이것도 Claude에게 물어보면 돼요. 버그가 나면 에러 메시지 복사해서 보여주면 되고, 기능 추가하고 싶으면 설명하면 됩니다. 저도 지금 계속 개선하고 있어요."

### 질문 9: "다른 사람과 함께 해도 되나요?"
**답변:**
"물론이죠! 오히려 같이 하면 더 좋아요. 서로 질문하고 답하면서 배울 수 있거든요. 스터디 그룹 만들어서 하는 것도 추천드려요."

### 질문 10: "선생님 프로그램 실제로 볼 수 있나요?"
**답변:**
"물론이죠! (스마트폰 꺼내서) 여기 제가 만든 앱이에요. 직접 보여드릴게요. (라이브 데모) 이게 다 Claude와 함께 35일 만에 만든 거예요."

## 자신감 키우는 법

### 강의 전 걱정된다면:

#### 1. 리허설 많이 하기
- 혼자 5번
- 가족 앞에서 2번
- 동료 앞에서 1번
- → 8번 하면 자신감 생김

#### 2. 발표자 노트 숙지
- 처음부터 외우려 하지 말기
- 핵심 키워드만 기억
- 나머지는 자연스럽게 설명

#### 3. 청중 시선 연습
- 카메라 보고 연습
- 녹화해서 보기
- 시선, 제스처 확인

#### 4. 긍정적 자기 암시
❌ "내가 잘할 수 있을까?"
✅ "나는 실전 경험이 있다. 청중에게 용기를 줄 수 있다."

### 강의 중 당황스러운 상황 대처:

#### 1. 질문에 답을 모를 때:
"좋은 질문이에요! 저도 그 부분은 아직 경험해보지 못했어요. 같이 찾아볼까요?" (솔직함이 신뢰를 만듦)

#### 2. 데모가 안 될 때:
"어? 아까는 됐는데... (웃음) 이게 바로 실전이에요. 이럴 때는 에러 메시지를 Claude에게 보여주면 됩니다. 한번 해볼까요?"

#### 3. 시간이 부족할 때:
"제가 너무 열심히 설명했네요. (웃음) 남은 내용은 자료로 드릴게요. 대신 질의응답 시간을 더 가지죠."

#### 4. 청중이 졸고 있을 때:
"자, 잠깐 스트레칭할까요? 10초만요. (일어나서) 이제 재미있는 실패 이야기 들려드릴게요."

## 마무리: 당신은 이미 자격이 있습니다

1. **실전 경험 > 이론 지식**
   - 당신은 해냈습니다
   - 그것만으로 충분합니다

2. **공감 능력이 최고의 무기**

   - 같은 어려움을 겪었습니다
   - 극복 방법을 알고 있습니다

3. **완벽할 필요 없습니다**
   - 솔직함이 신뢰를 만듭니다
   - "저도 몰라요"라고 말할 수 있는 용기
   - 함께 배워간다는 자세

4. **당신의 이야기가 힘입니다**
   - 59세 비전공자의 성공 스토리
   - 이것만으로 청중에게 용기를 줍니다
   - 당신은 증거입니다
