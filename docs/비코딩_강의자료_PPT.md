# 슬라이드 3: 비코딩이란?
## 비코딩(Vibe Coding)의 정의

### 비코딩 = 느낌으로 코딩하기?

**아닙니다!**

### 진짜 뜻:
> **AI 도구를 활용해서, 코딩 지식 없이도
> 원하는 프로그램을 만드는 새로운 개발 방식**

---

### 📝 발표자 노트 (슬라이드 3)

"비코딩"이라는 말을 들으면 어떤 느낌이 드시나요?

"느낌으로 코딩한다"는 뜻일까요? (웃음)
비빔밥처럼 대충 섞어서 만든다는 뜻일까요?

**전혀 아닙니다.**

비코딩의 "비(非)"는 "아니다"라는 뜻입니다.
즉, **"코딩이 아니다"** 라는 뜻이죠.

더 정확히 말하면:
- 전통적인 방식의 코딩이 아니다
- 프로그래밍 언어를 외울 필요가 없다
- 대신 AI에게 **한국말로 설명**하면 된다

**예를 들어볼까요?**

전통적인 개발:
```
"Python Django를 설치하고, 모델을 정의하고,
뷰를 작성하고, URL을 라우팅하고..."
```

비코딩:
```
"고객 정보를 저장하는 페이지를 만들어줘"
```

차이가 느껴지시나요?

# 슬라이드 4: 기존 개발 vs 비코딩
## 무엇이 다를까요?

| 구분 | 전통적인 개발 | 비코딩 (AI 활용) |
|------|-------------|---------------|
| **배경 지식** | 프로그래밍 언어 필수 | 한국어만 가능하면 OK |
| **학습 기간** | 6개월~2년 | 2-4주면 시작 가능 |
| **도구** | 코드 에디터, 터미널 | Claude Code 등 AI 도구 |
| **작업 방식** | 코드를 직접 작성 | AI에게 설명하고 확인 |
| **문제 해결** | 스택오버플로우 검색 | AI에게 물어보기 |
| **결과물 품질** | 전문가 수준 | **실전 사용 가능한 수준** |

---

### 📝 발표자 노트 (슬라이드 4)

자, 그럼 전통적인 개발과 비코딩이 뭐가 다른지 비교해볼까요?

**첫 번째: 배경 지식**

전통적인 개발을 하려면:
- Python이라는 언어를 배워야 하고
- Django라는 프레임워크를 배워야 하고
- HTML, CSS, JavaScript도 배워야 하고
- 데이터베이스도 이해해야 합니다

이게 뭔 말인지 모르셔도 됩니다. 저도 잘 모릅니다. (웃음)

비코딩은?
- 한국어만 할 줄 알면 됩니다
- "고객 목록을 보여주는 페이지 만들어줘"
- 이렇게 말하면 됩니다

**두 번째: 학습 기간**

전통적인 개발:
- 프로그래밍 기초: 3-6개월
- 웹 개발: 6-12개월
- 실무 수준: 1-2년

비코딩:
- 기본 개념: 1주
- 실전 적용: 2-4주
- 저는 35일 만에 완성했습니다

**세 번째: 작업 방식**

전통적인 개발자는 이렇게 일합니다:
```python
def get_customer_list(request):
    customers = Customer.objects.all()
    return render(request, 'list.html', {'customers': customers})
```

비코딩 개발자(저)는 이렇게 일합니다:
```
"고객 목록을 가져와서 화면에 표시해주세요.
이름, 전화번호, 주소가 보이면 좋겠어요."
```

**중요한 질문**: 결과물 품질은 어떨까요?

놀랍게도, **실전에서 사용할 수 있는 수준**입니다.
제가 만든 앱은 지금 실제 고객사에서 테스트 중입니다.

# 슬라이드 6: 실제 작업 예시 1
## "고객 전화번호를 정리하고 싶어요"

### 🗣️ 제가 한 말:
> "ERP에 있는 휴대전화 번호(010)를 찾아서
> Django 데이터베이스의 '휴대전화' 컬럼에 넣어주세요"

### 💻 AI가 한 일:
1. ERP 데이터 분석 스크립트 생성 (200줄)
2. 전화번호 형식 검증 로직 작성
3. 배치 처리 (한 번에 200명씩)
4. DRY RUN 모드 (안전하게 미리 확인)
5. 실제 업데이트 실행

### ✅ 결과:
- 1,886명 고객 데이터 처리
- 93개 휴대전화 번호 정리 완료
- **소요 시간: 30분**

---

### 📝 발표자 노트 (슬라이드 6)

실제 예시를 하나 보여드리겠습니다.

**문제 상황:**

우리 회사는 오래된 ERP 시스템을 쓰고 있습니다.
고객 전화번호가 두 개 컬럼에 나뉘어 있었어요:
- TEL1: 일반전화를 넣는 곳
- TEL3: 휴대전화를 넣는 곳

그런데 실제로 보니까 엉망이었습니다:
- TEL1에 휴대전화가 들어있고
- TEL3에 일반전화가 들어있고
- 어떤 건 둘 다 비어있고

**전통적인 방법:**

IT 부서에 요청하면:
1. 요구사항 정리: 1주
2. 개발: 2-3주
3. 테스트: 1주
4. 배포: 1주

총 5-7주 걸립니다.

**비코딩 방법:**

저는 Claude Code에게 이렇게 말했습니다:

"ERP에 고객 전화번호가 TEL1, TEL3 두 곳에 있어.

Django 데이터베이스의 '휴대전화' 컬럼에 넣어줘.
단, 실수하면 안 되니까 미리 확인할 수 있게 해줘."

그랬더니:

1. **분석 스크립트**를 만들어줬습니다
   - ERP에 휴대전화가 몇 개나 있는지 확인

2. **동기화 스크립트**를 만들어줬습니다
   - 010 번호만 골라내기
   - 중복 확인하기

4. **실행**
   - 확인 후 실제 업데이트
   - 1,886명 처리

**소요 시간: 30분**

제가 한 일:

- 결과 확인: 1분
- 실제 업데이트 실행: 1분

전체: 30분

전통적인 방법: 5-7주
